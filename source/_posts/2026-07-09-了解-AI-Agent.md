## 未来 5～10 年，技术发展的主线

如果站在 2026 年来看，技术行业已经进入了一个新的阶段：**AI 不再只是一个行业，而是成为所有行业的基础设施。** 未来 5～10 年，技术发展的主线可以概括为一句话：**AI Agent + 云计算 + 数据 + 自动化，将重塑软件开发和企业运营。**

### AI 从"工具"进入"员工"阶段（最大的趋势）

- 2023 年以前
  - AI 主要是：
    - ChatGPT
    - Midjourney
    - Copilot
      都是辅助工具

- 现在正在进入：
  - **AI Agent（智能代理）**

- 例如，Cursor 已经可以：
  - 修改整个项目
  - 自动修 Bug
  - 自动写测试
  - 自动提交代码

- 未来：
  - 一个 Agent 可以完成：产品需求 → 设计数据库 → 写接口 → 写前端 → 部署 → 上线
  - 人只需要负责：
    - 提需求
    - 做决策
    - Review

### 软件开发方式正在改变

- 过去：程序员 → 写代码 → 测试 → 部署

- **未来：程序员 → 描述需求 → AI 写代码 → AI 测试 → AI 修 Bug → AI 部署 → 人工 Review**

- 所以以后：
  - 写代码的重要性会下降

  - 更重要的是：
    - 架构能力
    - 产品思维
    - 业务理解
    - AI 协作能力

### 全栈越来越重要

- 以前：前端、后台、数据库、运维、测试，都是独立岗位
- 未来：越来越像 全站 + AI，更需要**能做完整产品的人**，因为不会写代码，AI 可以写，但是要怎么设计系统还是需要人来决定

## 如何理解 Agent

### Agent 概念

- 很多人以为 Agent 是一种新的 AI 模型，其实 **Agent 并不是模型，而是一种让大模型能够"完成任务"的软件架构**
- 一句话概括：
  - **Agent = LLM（大模型） + Memory（记忆） + Planning（规划） + Tools（工具） + Feedback（反馈循环）**
    - LLM（大脑）：负责理解问题、推理和决策。
    - Planning（规划）：把大目标拆成多个小步骤。
    - Memory（记忆）：保存上下文、历史执行结果、项目知识。
    - Tools（工具）：真正执行操作，比如读写文件、调用 API、运行命令。
    - Loop（循环）：不断根据最新结果调整计划，直到完成任务
      它们各司其职，职责很清晰
  - 或者更简单：**Agent = 一个能够自己思考、自己调用工具、自己检查结果、直到完成目标的程序**

### 我们先看看 ChatGPT 为什么不是 Agent

假设你问：帮我写一个 SpringBoot 登录接口

- ChatGPT 会：收到问题 → 思考 → 生成答案 → 结束
  - 整个过程只有一次推理
  - 它不会：创建文件、修改项目、编译、修改BUG 等等，因为它没有这个能力，**更像是聊天机器人**
- Agent 会发生什么？
  > 收到任务 → 分析项目 → 找到对应功能/代码位置 → 修改代码 → 运行测试 → 发现报错 → 继续修改 → 重新测试 → 成功 → 结束
  - 它会 思考/行动/观察结果/继续思考/继续行动...，这个循环过程就是 Agent，**循环（Loop）也是 Agent 最核心的东西**
  - **Agent 是一种让大模型能够"完成任务"的软件架构**
    - 它的大脑其实还是 LLM，简单那理解为 **Agent 是 LLM 的外壳**
    - 它为什么能够操作电脑？
      - 因为它有 Tool

### Agent 类型

实际上，**Agent 并不是一种固定产品，而是一种架构思想**。 根据能力和应用场景，可以把 AI Agent 分成不同类型。

```bash
                   AI Agent
                       │
    ┌──────────────────┼──────────────────┐
    │                  │                  │
个人助手          Coding Agent       企业 Agent
(ChatGPT)         (Codex/Cursor)      (办公自动化)
    │                  │                  │
    └──────────────┬───┴──────────────────┘
                   │
              Multi-Agent
           (多个 Agent 协同)
```

- 其实，所有 Agent 都是在回答一个问题：**它在替谁工作？**
- 不同 Agent，它的 LLM 其实没有变，**真正变化的是 Tool**
  | Agent 类型 | Tool |
  | -------------- | ---------------------- |
  | Coding Agent（编程 Agent） | Git、Terminal、IDE |
  | Office Agent（办公 Agent） | Outlook、Word、Excel |
  | Browser Agent（浏览器 Agent） | Chrome、Playwright |
  | Data Agent（数据 Agent）| MySQL、ClickHouse、Spark |
  | Research Agent（研究 Agent） | Search、PDF、RAG |
  | Robot Agent（机器人 Agent） | Camera、Sensor、Motor |
  | Customer Agent（客服 Agent） | CRM、ERP、工单系统 |

#### Personal Agent（个人助手）

最简单也最好理解的类型

- 例如：
  - ChatGPT
  - Gemini
  - Claude

- 它们主要负责：
  - 回答问题
  - 写文档
  - 总结会议
  - 翻译
  - 学习

- 例如：
  - 1. 帮我写一份周报
  - 2. 解释什么是 Cursor

- 它们一般：输入 → 回答 → 结束，几乎没有复杂的执行

#### Coding Agent（编程 Agent）

这是目前发展最快的方向

- 例如：
  - Cursor Agent
  - OpenAI Codex
  - Claude Code
  - OpenHands

- 它们会：
  - 阅读整个项目
  - 修改多个文件
  - 编译
  - 跑测试
  - 修 Bug
  - 提交 Git

- 例如：
  - 1. 给支付模块增加一个xx弹窗...
- 这种已经不是在聊天，而是在完成开发任务

#### Office Agent（办公 Agent）

帮助企业员工工作

- 例如：
  - 微软 Copilot

- 它们会：
  - 查看日历
  - 读取邮件
  - 生成会议纪要
  - 安排下次会议
  - 通知参会人
  - ...

- 例如：
  - 1. 今天有哪些会议？

## OpenAI Codex

### OpenAI 的产品有哪些？

- ChatGPT（面向个人）
  - Chat，基础聊天机器人
  - Projects
  - GPTs
  - Canvas
  - Deep Research
  - Codex，定位是 Coding Agent，负责软件开发

- Developer Platform（开发平台）
- 企业产品

### Codex 是什么？

**Codex 是 OpenAI 面向软件开发的 AI Agent，它的目标不是回答编程问题，而是完成软件开发任务**

- ChatGPT = AI 助手
- Codex = AI 软件工程师

### 使用 Codex

目前主要有几种方式

1.  [ChatGPT](https://chatgpt.com/) 中使用（推荐）

    如果你的 ChatGPT 账户支持 Codex，可以直接在 ChatGPT 中启动 Codex 工作流

    适合：
    - 修复项目
    - 阅读仓库
    - 长时间开发任务
    - Code Review

    Codex 已经集成到 ChatGPT，不需要单独安装

2.  [Codex](https://openai.com/zh-Hans-CN/codex/) 桌面应用

    OpenAI 提供了适用于开发者的 Codex 应用，可以连接本地项目并执行编码任务，根据套餐不同，可使用不同的模型和任务额度
    <img src="/images/了解-AI-Agent/codex.png" alt="image" class="max700 border1"/>
    <img src="/images/了解-AI-Agent/codex_for1.png" alt="image" class="max600 border1"/>

3.  API

    如果你想开发自己的 AI 编程工具，可以通过 OpenAI API 使用模型，自行实现 Agent、工具调用和工作流

    这种方式适合：
    - 企业内部 Coding Agent
    - 自动修 Bug 系统
    - PR
    - AI DevOps

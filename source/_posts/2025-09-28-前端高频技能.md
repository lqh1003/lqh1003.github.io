### "各端显示差异性"的兼容/适配处理能力

#### 各端介绍：

- PC 端：`Chrome`、`Firefox`、`IE`、`Microsoft Edge`、`UC 浏览器`等
- 移动端：`iOS Safari`、`Android Chrome`等
  - 平台默认浏览器：
    - 安卓系统/手机：**默认浏览器多样化，取决于厂商和用户设置**，一般是默认 `QQ 浏览器`
    - 苹果 IOS 系统/手机：统一，传统上使用 `Safari`，iOS 14+支持更改默认浏览器
  - 手机的版本 —— 截至 2025 年 9 月
    - 安卓手机的最新版本是 `Android 15`
    - iOS 手机的最新版本是 `iOS 19`
- 小程序：微信小程序、支付宝小程序等

#### 问题场景：

- IOS Safari 中 `position: fixed` 在滚动是抖动
- Firefox 中 flex: 1 计算逻辑与 Chrome 不一致
- IE 不支持 CSS Grid 布局
- 盒模型差异：IE 浏览器的盒模型和 W3C 标准盒模型计算方式不同，IE 的 content 包含 border 和 padding，而标准盒模型的 content 不包含
- 伪类/伪元素兼容性：部分伪元素，如`::before`、`::after`在旧版浏览器中需要双冒号，而 IE8 及以下仅支持单冒号
- CSS 动画兼容性：@keyframes 动画在旧版 IE 中不支持，或需要特定前缀
- ES6+ 语法兼容性：老版本浏览器不支持 ES6 + 的新语法，如 let、const、箭头函数等，在 IE 中会报错
- API 兼容性：部分原生 API，如 fetch、Promise、Array.prototype.includes 在旧浏览器中不存在
- 事件处理差异：IE 的 `attachEvent` 与标准的 `addEventListener` 不同，IE 中事件对象通过 window.event 获取，且 event 对象的属性也与标准浏览器有差异，如 IE 下 event 对象有 x、y 属性，但没有 pageX、pageY 属性，而 Firefox 下则相反
- DOM 操作差异：某些 DOM 方法，如`Element.insertAdjacentHTML()`在旧版浏览器中不支持
- 语义化标签兼容性：IE8 及以下不识别`<header>`、`<nav>`、`<footer>`等语义化标签
- 表单元素新特性兼容性：如 `input(type="date")` 在部分浏览器中会降级为普通文本框

#### 解题思路：

- 低版本浏览器（如 IE11、旧版 Chrome/Safari）不支持 Es6+ 和 新 API（通过工具链将高版本 JS 代码转换为低版本可识别的语法，并补充缺失的原生 API）：
  - 核心工具链：Babel + polyfill 组合（ES6+ 兼容的核心依赖两个工具）
    - **Babel**：负责将 ES6+ 语法（如箭头函数、let/const、解构赋值、类）转换为 ES5 语法
    - **Polyfill**：负责补充低版本浏览器缺失的 ES6+ 原生 API（如 Promise、Array.prototype.includes、Object.assign）
  - 内核判断：通过 navigator.userAgent 精准识别浏览器内核（如 Safari 对应 AppleWebKit，IE 对应 Trident），针对性加载 CSS 补丁（如给 IE 单独引入 grid-polyfil）
- CSS 属性，浏览器兼容性处理（补充浏览器私有前缀）:
  - `-webkit-`：用于 Chrome、Safari、新版 Opera 浏览器以及几乎所有 iOS 系统中的浏览器，简单来说，就是所有基于 WebKit 内核的浏览器
  - `-moz-`：用于 Firefox 浏览器，其内核为 Gecko
  - `-o-`：用于旧版 WebKit 之前的 Opera 浏览器，现在的 Opera 浏览器已基于 Blink 内核，一般情况下较少使用该前缀
  - `-ms-`：用于 IE 浏览器和 Chromium 之前的 Edge 浏览器
- 除此之外的其他兼容性处理（具体问题具体分析）
  - 盒模型：`box-sizing` 控制标准盒模型 **content-box**、IE 盒模型 **border-box**
  - iOS Safari 中 fixed 抖动：改用粘性布局 sticky 代替、或其他方法
  - `::-webkit-scrollbar` 在 Firefox 和旧版本的 Edge 浏览器上兼容性不一样，无法使用纯 CSS 来自定义滚动条样式
  - 在不同浏览器上，html 根元素的默认 font-size 不一致

### 性能优化：突破常规的"极限调优"能力

常规优化（如路由懒加载、图片压缩、资源优化、Terser/Gzip 压缩）后，页面仍存在 "首屏加载慢（>3s）"、"长列表滚动卡顿（FPS<30）"、"大型表单操作延迟" 等问题，需从渲染原理、浏览器底层机制切入优化

- 问题场景：首屏依赖多个 JS/CSS 文件，资源加载阻塞渲染，导致白屏时间长

  - 解决思路：
    - 关键 CSS 内联，将首屏必须要的 CSS 内联到`<head></head>`中，避免外部 css 文件加载组数渲染，（非关键 CSS 用 media="print" 标记，延迟加载）
    - JS 加载策略分级
      - 核心交互 JS（如登录验证）用 async 加载（不阻塞 DOM 解析，加载完立即执行）
      - 非首屏 JS（如统计脚本）用 defer 加载（不阻塞 DOM 解析，DOM 加载完执行）
      - 超大型 JS（如可视化图表库）用 "动态 import + 按需加载"，且在首屏渲染完成后（如 window.load 事件后）再加载
    - 预加载与预连接
      - 用 `<link rel="preload" href="critical.js" as="script">` 预加载关键资源
      - 用 `<link rel="preconnect" href="https://api.xxx.com">` 提前建立与接口域名的 TCP 连接，减少 DNS 解析和 TCP 握手时间
  - `<script>` 标签用于在 HTML 中嵌入或引用 JavaScript 代码，其属性用于控制脚本的加载、执行方式及行为。以下是 `<script>` 标签的核心属性及用法
    - src 指定外部 JavaScript 文件的 URL（路径），用于引入外部脚本（替代内嵌脚本）
    - type 指定脚本的 MIME 类型（通常用于标识脚本语言），默认值为 text/javascript（可省略）
      - `<script type="module" src="./module.js"></script>`
      - module：表示脚本为 ES6 模块（支持 import/export 语法），浏览器会按模块规则加载（如延迟执行、严格模式）
    - charset 指定外部脚本文件的字符编码（如 UTF-8）
    - async 异步加载脚本，加载期间不阻塞 HTML 解析，加载完成后**立即执行**（执行时可能阻塞解析）
    - defer 延迟加载脚本，加载期间不阻塞 HTML 解析，**等待 HTML 解析完成后（DOM 就绪）按顺序执行**
    - ...

- 问题场景：1 万条数据的列表滚动时，频繁触发重排（Reflow），导致 FPS 过低、卡顿
  - 解题思路：
    - 虚拟列表进阶：在基础虚拟列表（只渲染可视区域）上，优化 "滚动位置计算"—— 用 requestAnimationFrame 替代 scroll 事件监听（减少触发频率），用 transform 替代 top/left 定位（transform 仅触发复合层渲染，不触发重排）
    - 数据分片与缓存：列表数据按 "可视区域 2 倍" 分片加载，避免一次性处理大量数据；对已渲染的 DOM 节点进行缓存（如用数组存储，滚动时复用，不重复创建）
    - 禁止滚动时的耗时操作：滚动过程中暂停 console.log、DOM 查询（如 document.querySelector）等耗时操作，待滚动停止后（用 debounce 延迟 100ms）再执行

### "复杂/高难度交互"的工程化实现能力

拖拽缩放：精准控制与边界处理

- 问题场景：拖拽元素时出现 "卡顿"、"超出容器边界"、"多层元素拖拽冲突"
  - 事件委托与阻止冒泡：将拖拽事件（`mousedown`/`touchstart`、`mousemove`/`touchmove`、`mouseup`/`touchend`）委托给父容器，避免给每个子元素绑定事件；通过 `event.stopPropagation()` 阻止多层元素的事件冲突（如子元素拖拽不触发父元素滚动）；
  - 坐标计算精准化：用 clientX/clientY（相对视口）而非 pageX/pageY（相对文档）计算拖拽位置，避免页面滚动影响坐标；拖拽边界判断时，结合元素宽高与容器宽高，用 Math.max/min 限制元素不超出容器（如 `left = Math.max(0, Math.min(clientX - offsetX, containerWidth - elementWidth))`）；
  - 性能优化：拖拽过程中用 requestAnimationFrame 更新元素位置，避免同步操作阻塞主线程；若元素有复杂样式（如阴影、渐变），可在拖拽时临时移除（用 class 切换），拖拽结束后恢复，减少渲染开销。
